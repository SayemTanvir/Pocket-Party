# Rebuilding the itch.io beta

The upload files are generated in `dist/itch/` and intentionally ignored by Git.

On this Windows workspace, run `./tool.ps1 -Task itch` to perform the complete build and packaging sequence below using the configured SDKs and caches.

1. Run `python tool/prepare_signing.py` once to create a local release signing identity. **Back up the entire `release-signing/` directory securely.** It contains the private key and password needed to update the Android app. Do not upload it to itch.io or GitHub. Existing credentials are never overwritten.
2. Configure the Flutter/Android environment as in `tool.ps1`.
3. Run `flutter build web --release --no-web-resources-cdn --dart-define=ROOM_SERVER=https://pocket-party-rooms.onrender.com`.
4. Run `flutter build apk --release --dart-define=ROOM_SERVER=https://pocket-party-rooms.onrender.com`.
5. Run `python tool/package_itch.py`.

The packager puts `index.html` at ZIP root, makes its base URL relative, includes local CanvasKit resources and checks itch.io's archive limits. It includes the Android release APK, generated cover and page copy in the output directory. Signing credentials and source files are never put in the upload archive.

The Android release application ID is `io.github.sayemtanvir.pocketparty`. Its release signing identity differs from the old development app, so the beta installs separately.

Artwork is generated by `tool/make_store_art.py` using Pillow. It uses original geometric artwork and Segoe UI fonts installed on this Windows machine. The generated PNGs are committed so a normal rebuild does not need Pillow.

Publishing instructions and exact page copy are in `PAGE.md`. A local build is not confirmation that the hosted itch.io iframe works: run the preview checks before making the page public.
